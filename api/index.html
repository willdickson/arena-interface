    API reference¶

    Everything below is importable from the package itself, e.g. from arena_interface import Device, Pattern, TrialMode. The modules are listed here only to group the reference by topic.

    Connecting and controlling¶

    device ¶

    High-level interface to a G6 arena controller.

    from arena_interface import Device, TrialMode

with Device.open() as dev:                # auto-detect
    print(dev.firmware_version)
    dev.start_trial(1, TrialMode.OPEN_LOOP, frame_rate=60, duration=5)

    Thread safety: a Device may be shared between threads. Each method is atomic (the wire protocol allows only one request at a time and the device serialises them), and multi-step methods such as PatternLibrary.upload hold a lock for their whole sequence. Sequences of calls made by your own code are not atomic; use your own lock if another thread must not interleave.

    Device ¶

    Device(
    transport: Transport,
    *,
    all_off_on_close: bool = True,
    arena_shape: tuple[int, int] | None = None,
    simulator: FakeController | None = None,
)

    A connection to one G6 arena controller.

    Create it with Device.open and use it as a context manager, or call close yourself. Closing blanks the arena (ALL_OFF) unless all_off_on_close is False.

    Feature groups are attributes: patterns (SD card), io (analog and digital BNCs), telemetry (event log), diagnostics and panel_firmware.

    Wrap an open transport; most code should use Device.open.

    Parameters:

    Name Type Description Default
    transport Transport

    Connected transport.

    		 required
    all_off_on_close bool

    Send ALL_OFF when closing.

    		 True
    arena_shape tuple[int, int] | None

    Panel rows and columns of the firmware build, for firmware that cannot report them.

    		 None
    simulator FakeController | None

    The simulated controller, when transport is a fake.

    		 None

    Raises:

    Type Description
    ProtocolError

    If the device does not identify as a G6 controller.

    arena property ¶

    arena: Arena

    The full panel grid the controller drives, as an Arena.

    open classmethod ¶

    open(
    port: str | None = None,
    *,
    simulate: bool | FakeController = False,
    probe: bool = True,
    all_off_on_close: bool = True,
    arena_shape: tuple[int, int] | None = None,
    cache_patterns: bool = False,
) -> Device

    Connect to a controller.

    Parameters:

    Name Type Description Default
    port str | None

    Serial port name. If omitted, the controller is found by its USB ids (see find_ports).

    		 None
    simulate bool | FakeController

    Connect to a simulated controller instead of hardware: True for a new default one, or a FakeController.

    		 False
    probe bool

    When several candidate ports are found, ask each one for its controller info to pick the controller. Without probing, more than one candidate is an error.

    		 True
    all_off_on_close bool

    Blank the arena when the connection is closed.

    		 True
    arena_shape tuple[int, int] | None

    (rows, cols) of the firmware build, for firmware too old to report it.

    		 None
    cache_patterns bool

    Read the SD card's pattern names now and keep them, so choosing a pattern by name is fast (see PatternLibrary.cache).

    		 False

    Returns:

    Type Description
    Device

    The connected device.

    Raises:

    Type Description
    DeviceNotFound

    If no controller is found, the choice is ambiguous, or the port cannot be opened.
    DeviceTimeout

    If the device does not answer.
    ProtocolError

    If the device does not identify as a G6 controller.
    Example

    with Device.open(simulate=True) as dev: ... print(dev.arena_shape) (2, 10)

    close ¶

    close() -> None

    Blank the arena (unless disabled) and release the port.

    Safe to call more than once and after the device has disappeared.

    reset ¶

    reset() -> None

    Reboot the controller (SYSTEM_RESET).

    The USB connection drops, so the device is closed afterwards; call reconnect to continue.

    reconnect ¶

    reconnect(
    timeout: float = 10.0, poll_interval: float = 0.25
) -> None

    Re-open the same controller after a reset or an unplug.

    Polls the port until the controller answers again. If the MAC address was known, it must match, so a different controller on the same port is not picked up by mistake.

    Parameters:

    Name Type Description Default
    timeout float

    Seconds to keep trying.

    		 10.0
    poll_interval float

    Seconds between attempts.

    		 0.25

    Raises:

    Type Description
    DeviceNotFound

    If the controller does not come back in time, or a different controller answers.

    start_trial ¶

    start_trial(
    pattern: int | str,
    mode: TrialMode = OPEN_LOOP,
    *,
    frame_rate: int = 0,
    initial_frame: int = 0,
    gain: int = 0,
    duration: float = 0.0,
    duty_cycle: int | None = None,
) -> None

    Start displaying an SD-card pattern.

    Parameters:

    Name Type Description Default
    pattern int | str

    The SD-card pattern: its file name (.pat optional, case ignored) or its id, its number in the alphabetical list of file names starting at 1 (see device.patterns). Ids change when patterns are added, renamed or deleted; names do not.

    		 required
    mode TrialMode

    Open loop (auto-advance), show frame (you choose the frame) or closed loop (frame rate follows Analog In 1).

    		 OPEN_LOOP
    frame_rate int

    Frames per second in open loop; negative plays backwards.

    		 0
    initial_frame int

    Frame to start on (the first frame is 0).

    		 0
    gain int

    Closed-loop gain in tenths of frames per second per volt.

    		 0
    duration float

    Seconds until the controller stops by itself; 0 = never.

    		 0.0
    duty_cycle int | None

    Brightness 1-255 for this trial, or None for the pattern's own.

    		 None

    Raises:

    Type Description
    KeyError

    If no pattern has that name.
    CommandError

    If the pattern cannot be loaded (the arena shows an error code briefly and goes dark).
    Example

    with Device.open(simulate=True) as dev: ... dev.start_trial("demo_gs2", frame_rate=30) # demo_gs2.pat ... dev.start_trial(1, frame_rate=30) # the first pattern

    pace ¶

    pace(
    rate_hz: float,
    *,
    duration: float | None = None,
    count: int | None = None,
    late: LatePolicy = "skip",
    refresh_rate: int | None = None,

    A fixed-rate clock for live (closed-loop) playback.

    Iterate over it and send one frame per tick, chosen as you go:

    pacer = dev.pace(200, duration=10)
for tick in pacer:
    dev.show_frame(choose_frame())
print(pacer.report)

    Parameters:

    Ticks per second.

    		 required
    duration float | None

    Stop after this many seconds (None: until you break).

    		 None
    count int | None

    Stop after this many ticks.

    		 None
    late LatePolicy

    "skip" jumps over ticks whose time has passed (the next tick says how many); "send" delivers every tick, late.

    		 'skip'
    refresh_rate int | None

    Set the controller's refresh rate first.

    		 None

    Returns:

    Type Description
    Pacer

    An iterable Pacer.

    Patterns and arenas¶

    pattern ¶

    Patterns from pixel arrays: build and read .pat files and stream frames.

    A Pattern holds one image per frame for a whole arena: rows * 20 pixels high and cols * 20 wide, with values 0/1 (GS2) or 0-15 (GS16). Images may be numpy arrays or nested lists; frames come back as numpy arrays.

    import numpy as np
from arena_interface import Arena, GrayLevel, Pattern

h, w = Arena.preset("G6_2x10").pixel_shape
x = np.arange(w)
stripes = [np.tile(np.where((x + f) % 20 < 10, 15, 0), (h, 1)) for f in range(20)]
pattern = Pattern.from_frames(stripes, gray_level=GrayLevel.GS16)
data = pattern.to_bytes()               # a .pat file

    Orientation: by default row 0 of an image is the top of the arena (origin="upper", as in numpy and matplotlib's imshow). Pass origin="lower" for row 0 at the bottom, the convention of the MATLAB and JavaScript tools. Columns run left to right either way.

    The library converts to the on-wire layout: panels in row-major order from the bottom row of panels, and within each panel block the first 20 pixels are the panel's top row (as the panel firmware reads them; see docs/PROTOCOL.md).

    Host-paced playback¶

    playback ¶

    Host-paced playback: the computer decides when each frame is shown.

    Three ways to use it, all on a Device:

    dev.show_pattern(4)
report = dev.play_frames(range(200), fps=200)        # frames of an SD pattern
report = dev.play_images(images, fps=120)            # streamed images

player = dev.start_frames(range(200), fps=200)       # same, in the background
report = player.wait()

for tick in dev.pace(rate_hz=200, duration=10):      # live: you choose each frame
    dev.show_frame(choose_frame())

    Timing: frames are scheduled against a fixed clock (no drift). The scheduler sleeps until just before each slot and then busy-waits for sub-millisecond accuracy. When a frame cannot be sent on time, late="skip" drops frames whose slot has passed so the sequence keeps its schedule, and late="send" sends every frame, so the sequence runs long. Either way the PlaybackReport says what happened, and falling behind is logged on arena_interface.playback.

    A frame is only displayed if it stays in place for at least one refresh of the controller, so fps should not exceed the refresh rate (dev.refresh_rate); a PerformanceWarning is issued if it does. Frames of an SD pattern also wait for the controller's SD read, which occasionally stalls, so at fps close to the refresh rate a frame can now and then be replaced unseen; play_frames(..., verify=True) reports it.

    Values returned by the device¶

    Request builders and response decoders for every controller command.

    Each command has a builder that validates its arguments and returns a Request: the bytes to send, the opcode the reply will echo, a suitable timeout, the kind of exchange, and the capability or firmware flag the device must advertise.     Simulated controller¶

    testing ¶

    A simulated G6 arena controller for tests, examples and development.

    FakePort behaves like a pyserial port connected to a controller. Behind it, a FakeController parses the bytes written to the port the way the firmware does and answers with the same replies: status codes, messages, payload layouts and side effects (error glyphs that stop the display, commands refused while the display runs, index shifts after deleting a pattern, and so on). It keeps an in-memory SD card, the telemetry ring and the I/O state.

    from arena_interface.testing import FakePort
from arena_interface.transport import Transport

with Transport(FakePort()) as link:
    ...

    The controller can also inject faults: unplugging the device, going silent, delaying replies, or emitting debug text. A controller outlives its ports, so a test can unplug, then connect a new FakePort(controller) to simulate a reconnect.

    What is not emulated: panel pixels (frames are accepted, not rendered), the precise wording of panel-programming messages, and refresh timing beyond a simple frames-sent estimate.
